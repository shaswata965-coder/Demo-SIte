Demo blueprint · v0.1 · 11 Sep 2026

A neural field for a fintech front page

A first position for the client demo, built in the spirit of totem.itsoffbrand.com — one object owns the centre of the screen and transforms as you scroll — with the totem replaced by a network that rewires itself through seven states. AXON is a fictional company; every figure in the prototype is invented.

Open the live prototype → The reference
01The idea

The network is the company

A fintech whose product is inference should have a homepage where you watch inference happen. The field above is not decoration sitting behind the copy — on the real page the copy narrates what the field is currently doing, and both are locked to the same scroll position. Scroll is the only input; there is no timeline running on its own.

02Design system

03Storyboard

Seven states, one object, no cuts

Scroll position maps onto a single number from 0 to 6. Its whole part picks the state, its fraction blends into the next. Each frame below is the field rendered at that exact value by the same code that drives the live prototype — these are not illustrations.

Edges fade, they never cut. Every edge carries a visibility weight per state, so a connection that belongs to the layered stack dims away as the globe forms instead of vanishing. That is the whole trick behind the object appearing to rewire itself.

04Stack

What to build it in

The brief has four constraints that pull against each other: an award-grade WebGL scroll experience, full responsiveness, a CMS a non-developer can run, and smooth playback on mid-tier hardware. The last one is the binding constraint — almost any stack satisfies the first three.

LayerChoiceWhy this one, for this brief
FrameworkNext.js 15 App Router, TSRoute-level splitting keeps the ~190 KB 3D bundle off pages that don't render the field. Marketing pages ship as CDN HTML, not a client-rendered shell.
3DReact Three Fiber + dreiDeclarative Three.js that reads React state, so scroll chapter and scene state are one source of truth. Instancing and LOD are ~30 lines, not a rewrite.
ChoreographyGSAP + ScrollTriggerScrubs a timeline against scroll position — exactly the reference's model. Framer Motion is better at component transitions, worse at long scrubbed timelines.
ScrollLenisThe inertial feel is much of what the client responded to. Smooths pointer-fine devices and correctly leaves native scroll alone on touch.
StylingTailwind v4Reads CSS custom properties directly, so one token file feeds both utilities and the canvas code.
CMSSanityStudio embedded at /studio in the same repo and deploy — and motion parameters become content. See below.
HostingVercelEdge CDN, image optimisation, a preview URL per branch for client review.

Why Sanity specifically

Beyond the usual — Portable Text, real-time collaboration, an embedded Studio — one thing matters here: motion parameters can be content. Scroll length per chapter, which morph state a chapter resolves to, accent hue, pulse density: all of it lives in the same document as the copy. On a site where the motion is the product, that's the difference between a site the client can run and a site they have to call us about.

05Mid-end devices

Three tiers, and a fallback that isn't embarrassing

Sites in this genre routinely ship 4 MB of JavaScript and hold 22 fps on a mid-range Android. That's the failure mode to design against. Budgets below are written against a Pixel 6a / Galaxy A54 class phone on throttled 4G.

The fieldLive WebGLLive WebGLScroll-scrubbed AVIF sequence

Tier C is a design, not an error state. Same copy, same seven chapters, same scroll length, same layout — the field becomes about 60 pre-rendered frames, roughly 400 KB total. Most visitors wouldn't identify it as a fallback. It is also what prefers-reduced-motion gets.

Tier is chosen once at boot from deviceMemory, hardwareConcurrency, the WebGL renderer string and saveData, then a frame-time governor demotes it and never promotes it — a tier that oscillates looks worse than one that is simply lower, and people notice the oscillation more than the resolution. The live prototype runs that same governor in miniature.

06Content model

Constraints worth enforcing in the Studio, not in a style guide

  • scrollChapter.body capped at 320 characters — the copy sits over a live canvas and stops being readable beyond that.
  • heroScene.headline capped at 60 characters — past that it wraps to more than four lines at 390 px wide.
  • Two consecutive chapters may not share a fieldState; the morph would be a no-op and the chapter change would read as broken.
  • Every media field requires alt. Enforced at schema level, no exceptions.

08Open

Four things I need from you

Whose brand

Is the demo dressed as the fictional AXON, as your own brand, or as a named prospect of yours? This changes phase 01 substantially.

The device floor

"Mid-end" needs a specific handset. Everything in section 05 is written against a Pixel 6a / Galaxy A54. If the real floor is lower, tier C becomes the default rather than the fallback — a decision to make deliberately, not discover at QA.

Who edits after launch

A marketer or an engineer? The CMS recommendation holds either way, but how much of the motion we expose as editable content depends on the answer.

Audio

The reference has an audio layer and it's a signature part of the genre. It also carries real autoplay-policy and accessibility cost. In or out?
